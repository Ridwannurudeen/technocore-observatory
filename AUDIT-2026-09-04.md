# Audit review — 2026-09-04

Baseline: `b274f8c31a2da6e56077ed64dccbac8307f111eb` (`main` and
`origin/main` at review time). Each change set was reviewed independently with
`git diff b274f8c <sha>` before integration.

## `6338934` — collector

- **rejected** — The relaxed sub-second origin-event check does not trip an
  unrevised `derive.py` validator. `validate_event` validates the timestamp's
  syntax but does not compare it with the tick timestamp; the lifecycle
  selection timestamp remains the tick timestamp and still matches
  `validate_room_lifecycle_sampling`. The engagement projection also remains
  accepted because `validate_engagement` normalizes absent, ill-typed and
  out-of-range retained values instead of rejecting a tick. Census failure
  causes and read-budget fields remain within their existing validators.
- **confirmed** — The collector changes its published evidence contract without
  moving `COLLECTOR_VERSION` from `2.14.0`. It newly discards unrecognized or
  non-scalar engagement members, changes accepted origin-event timing, and
  changes census failure-cause publication. These are real collector contract
  changes and require a collector version bump.
- **confirmed** — The new "collection committed; publication deferred" path
  does not cover a real failure after the SQLite outbox commit. `collect_tick`
  commits the outbox and then writes `signers.json`; if that write raises, the
  function never returns and `main` leaves `outbox_committed` false, reporting
  "collection failed; no tick written" even though a replayable tick is
  committed. `test_main_reports_a_committed_tick_whose_publication_is_deferred`
  mocks `collect_tick` to return successfully and therefore asserts the local
  flag implementation rather than the transaction boundary that matters.
- **rejected** — The revised 2.14.0 deployment note matches the executable
  order. `main` drains the tick outbox before `collect_tick`, and an existing
  signer database is opened by that drain, which runs the one-time schema and
  trigger validation before the tick deadline starts.

## `98766c3` — derive

- **confirmed** — The retention-boundary expectation still misses one absent
  tick in a partial opening bucket. `int(covered_seconds //
  expected_tick_seconds)` counts complete intervals, not cadence observations
  when the lower boundary is inclusive. `max(len(points), expected)` makes a
  perfect bucket look correct, but if one interior observation is absent the
  observed length falls to the floored value and `missing_count` incorrectly
  remains zero.
- **confirmed** — `README.md` and `DEPLOY.md` declare methodology `1.16.0`, and
  the methodology resource contains its change history, but `API.md` still
  stops at methodology `1.15.0`. The frozen public-contract document therefore
  omits the current changes to gap semantics, rollup shape, null cumulative
  values, and sampling denominators.
- **rejected** — The methodology bump from `1.15.0` to `1.16.0` is warranted.
  The commit changes published field meaning (`coverage.sampled_rooms`), adds
  `coverage.selected_rooms` and `gaps[].cadence_gap`, removes rollup `sum`, and
  changes gap counts, rollup completeness and null-series behavior.
- **rejected** — The selected-versus-successful sampling split is carried
  consistently: the validated funnel keeps successful reads in
  `sampled_rooms`, the derived merged coverage takes manifest selections into
  `selected_rooms`, and both the funnel and sampling displays read the intended
  denominator.

## `1b920a5` — rebuild and snapshots

- **confirmed** — `rebuild.sh` does not guarantee the promised locked ledger
  snapshot. If `ticks.jsonl.lock` is absent it copies `ticks.jsonl` without a
  lock and without a warning; if `flock` fails it warns and performs the same
  unlocked copy. A collector can create/acquire the lock and append during
  either copy. The accompanying test searches the shell source for a `flock`
  command and shared copy path, so it asserts implementation text and misses
  both unlocked paths.
- **confirmed** — The status envelope does not always date from the oldest
  displayed component observation. It compares the latest tick with the latest
  attempt of any route, while the displayed origin component is dated from the
  latest `/healthz` attempt. Fresh collector `/rooms` attempts can therefore
  mask a stale origin probe, contradicting `API.md`'s statement that one dead
  source is never masked by a live one. The new test contains only a health
  attempt and does not exercise this production mix.
- **confirmed** — Published snapshot contracts change without all applicable
  version moves. Status and changes `source_observed_at` semantics change and
  `coverage.last_change_observed_at` is added while API `contract_version`
  remains `1.0.0` and methodology remains `1.15.0` in this independent change
  set. Separately, REGIME's `interpretation_affected` classification changes
  while `INCIDENT_RULES_VERSION`, which stamps those change records, remains
  `1.0.0`.
- **confirmed** — The `API.md` statement that status uses the oldest component
  is not what the code does in the fresh-collector/stale-health case above. Its
  general field description also still calls `source_observed_at` the newest
  observation used without stating the status exception.
- **follow-up** — `test_guards_validate_the_static_release_before_rendering_it`
  compares source-code substring positions. The current call order is correct,
  so this is not evidence of a production defect, but a later refactor can
  preserve behavior and fail the test. Replace it with an observed call-order
  test when the guard runner is next changed.

## `f06c95c` — site and query service

- **confirmed** — The public query contract changes while API
  `contract_version` remains `1.0.0`. Search now rejects Unicode format, line
  separator and paragraph separator characters that the prior contract
  accepted, and the query service now regenerates snapshot `generated_at` and
  freshness on unfiltered responses as well as filtered ones. This requires an
  API contract version bump and matching footer/documentation updates.
- **confirmed** — The pre-paint theme scripts and theme persistence handlers add
  empty `catch {}` blocks. They intentionally tolerate unavailable web storage,
  but silently discarding that state violates the repository's error-handling
  rule. The failure should be handled explicitly while retaining the system
  theme and keeping the control usable.
- **rejected** — The requested progressive-enhancement behaviors are correctly
  implemented. Theme controls remain hidden without script and are revealed
  only after their driver runs; stored light/dark choice is applied before the
  stylesheet; both range-thumb engines receive a 24 by 44 pixel target; and
  lifecycle sampling fields are overwritten with an explicit not-recorded pair
  when an older tick lacks evidence.
- **follow-up** — `test_idle_connections_are_bounded_by_a_socket_timeout`
  asserts only `ObservatoryRequestHandler.timeout == 10`. The inherited
  `StreamRequestHandler` currently consumes that attribute, so no runtime bug
  is established, but the test should eventually exercise socket timeout
  application rather than the chosen implementation mechanism.
- **follow-up** — `test_query_shell_classes_are_grid_children_with_stylesheet_rules`
  scans CSS source for class-name selectors. That is an implementation-shape
  check, not proof of computed styling or grid-child layout. The browser reflow
  test supplies some behavioral coverage, so this does not block integration.
